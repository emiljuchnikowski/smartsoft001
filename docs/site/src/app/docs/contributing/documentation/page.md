This site is an Nx project, `docs`, built from Markdoc pages in `docs/site/src/app`. Every code sample on a reference page is cut from a file that CI compiles and tests, and a parity check fails the pipeline when the workspace and the pages drift apart. {% .lead %}

---

## Where pages come from

| Section               | Source                                                                                                                                                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Getting started, CRUD | Hand-written pages under `docs/site/src/app/docs/`.                                                                                                                                                                             |
| Packages              | One hand-written page per `@smartsoft001/*` package from the template `docs/site/tools/templates/package-page.md`.                                                                                                              |
| Components            | Generated by `nx run docs:generate-components` from the plugin's `angular-components-*` skills; hand-written pages for components without a skill live in `docs/site/content/components/`. The generated pages are git-ignored. |
| Skills                | Hand-written pages from `docs/site/tools/templates/skill-page.md`; the header of each skill page is expanded from the skill's frontmatter by the `{% skill %}` tag.                                                             |
| Contributing          | Hand-written pages, this section.                                                                                                                                                                                               |

The navigation is generated from page frontmatter (`title`, `section`, `order`) by `nx run docs:generate`; sections and their order are listed in `docs/site/tools/sections.mjs`.

## Code samples

Reference pages never contain hand-written code. A sample is a region of an executed file embedded with the `snippet` tag:

```markdown
{% snippet file="node/src/models/field.example.ts" region="usage" /%}
```

- `file` is relative to `docs/examples` (include the `src/` segment), or repo-relative when it starts with `packages/`, which is how component pages embed the `usage` region of a Storybook story.
- A region is delimited by `// #region name` and `// #endregion` (also `/* */`, `<!-- -->` and `# #region` for shell files). The tag is expanded before Markdoc sees the page, so a missing file or region breaks the build.
- Examples live in the `docs-examples-node` and `docs-examples-angular` projects, each `*.example.ts` next to a `*.example.spec.ts` that runs in CI without network or database access. Every example is wrapped whole in a `usage` region.
- A live Storybook story is embedded with `{% storybook project="angular" story="components-button--playground" /%}`; both Storybooks are built, smoke-tested and copied next to the site by the `Docs` workflow.

## Adding a page

The [`docs` skill](/docs/contributing/docs) runs every step below for you and then runs the checks;
what follows is what it does, and what to do when you write a page by hand.

- **Package**: copy `templates/package-page.md` to `docs/packages/<name>/page.md`, write the example under `docs/examples/node/src/<name>/` or `docs/examples/angular/src/<name>/`, keep the `Install`, `Usage` and `API` headings.
- **Component**: nothing to write when the component has an `angular-components-<name>` skill; add a `// #region usage` around the `Playground` story and, optionally, `docs/examples/angular/src/components/<name>/custom.example.ts` for the "Extending the base class" section. A component without a skill gets `docs/site/content/components/<name>.md` from `templates/component-page.md`.
- **Skill**: copy `templates/skill-page.md` to `docs/skills/<name>/page.md`; `title` and `skill` are the skill name, the `{% skill %}` tag renders the header.

## Checks

`nx run docs:check` runs `tools/scripts/docs-check.mjs`. The parity rules compare the workspace with the pages and are enforced as errors by CI; the remaining rules are always errors.

| Rule | Checks                                                                                  |
| ---- | --------------------------------------------------------------------------------------- |
| R1   | Every publishable package has a page under `docs/packages`.                             |
| R2   | Every UI component has a page under `docs/components`.                                  |
| R3   | Every user-invocable skill has a page.                                                  |
| R4   | Every `snippet` tag points at an existing file and region.                              |
| R5   | Every `storybook` tag points at a story that exists.                                    |
| R6   | Reference pages embed snippets and never inline TypeScript or HTML.                     |
| R7   | Every page declares a title and a known section.                                        |
| R8   | Every package page names its package and follows the skeleton.                          |
| R9   | Every UI component has a story with a `usage` region.                                   |
| R10  | Every skill reference points at an existing skill and the page title is the skill name. |
| R11  | Every fenced code block declares a language.                                            |
| R12  | Every package belongs to exactly one meta package.                                      |
| R13  | Every component page documents its usage in a tabs block.                               |
| R14  | Every `docs/examples/app` path a `SKILL.md` cites exists in the workspace.              |

Locally, `nx run-many -t check test build lint -p docs docs-examples-angular docs-examples-node` is the same set the workflows run. `nx run docs:serve` starts the site on port 3000 without the Storybook builds, so story embeds show an empty frame there.

## Deployment

The `Docs` workflow runs after every successful `Publish` on `main` (and on demand): it verifies the packages install from npm, builds and smoke-tests both Storybooks, checks, tests and builds the site, verifies every embedded story id against the built Storybook index and deploys `docs/site/out` to GitHub Pages.
